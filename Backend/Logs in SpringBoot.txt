1. Spring Boot supports various logging frameworks, such as LogBack, Log4j2, and Java Util Logging(JUL).
2. LogBack: A popular logging framework that serves as the default in many Spring Boot applications. It offers a flexible configuration and good performance.
   Log4j2: Another widely used logging framework that features with features such as asynchronous logging and support for various output formats.
   Java Util Logging(JUL): The default loggin framework included in the Java Standard Edition. While it's less feature-rich than some third party frameworks, it is straightforward and is 
			   part of the Java platform.

3. Spring Boot comes with a default logging configuration that uses Logback as the default logging implementation. It provides a good balance between simplicity and flexibility.

4. The default configuration is embedded within the Spring Boot libraries, and it may not be visible in your project's source code.

5. If you want to customize the logging configuration, you can create your own logback: spring.xml or logback.xml file in the src/main/resources directory.
   When Spring Boot detects this file in your project, it will use it instead of the default configuration.

6. Loggin levels help in categorizing log statements based on their severity. The common logging levels are:
	Trace, Debug, Info, Warn, Error

7. We can set the desired logging level for specific packages or classes, allowing them to control the amount of information logged at runtime.
   By default loggin is enabled for Info, Warn, Error

8. Spring Boot provides annotations like @Slf4j and @Log4j2 that you can use to automatically inject logger instances into your classes.

9. private static final Logger logger = LoggerFactory.getLogger(JournalEntry.class);
   Every logger is associated with specific class. We will have sperate instance of Logger for every class and by default we will make it private static and final.

10. If you use "sl4j" of lombok, you don't need to make instance of Logger everytime, it will automatically inject it and you can use it:
	Example: 
		import lombok.extern.slf4j.Slf4j;

		@Slf4j
		public class MyService {
			public void doSomething() {
				log.info("Do something!");
			}
		}

11. Spring Boot allows us to configure logging using properties or YAML files.

12. Default logging is enabled for Info, Warn, Error. To enable logging for other logs, you can enable them in yml file:
	logging:
	  level:
	    com:
	      abd:
	        journalApp: DEBUG

13. If you put log to error, then only logs with severity error and more will be printed.
    The above logging is applied to journalApp, that's why logs will be applied to journalApp. Every other package log will be printed as it is.
    For example, in the above example if i have made the log of journalApp to "ERROR", then only "ERROR" logs will be printed as no other log is severe than "Error", but 
    Info logs of root will print as it is.

    If you don't want to print "INFO" logs of root, then you can change it in "yml":
	logging:
		level:
			root: OFF

    Same can be achieved by "xml" file.

1. <configuration>
	<!--  Appender and Logger configurations go here -->
   </configuration>

   The <configuration> element is the root element of the logback.xml file. All Logback configuration is enclosed within this element.
   Appender:
	An appender is a component responsible for outputting log messages to a specific destination, such as:
		Console
		File
		Database
		Remote server
		GUI component

	Each appender defines how and where the log messages will be delivered.
