Design Patterns
1. What are Design Patterns?
	Design Patterns are proven solutions to common software design problems.
	They are not code, but templates/blueprints that help you design flexible, reusable, and maintainable software.
	Introduced by the “Gang of Four” (GoF) in the book Design Patterns: Elements of Reusable Object-Oriented Software (1994).

2. Why use Design Patterns?
	Promote code reusability.
	Improve communication (developers share a common vocabulary).
	Make software more flexible & maintainable.
	Help in applying SOLID principles effectively.

3. Categories of Design Patterns
	Design patterns are mainly divided into three categories:

	1️⃣ Creational Patterns (Object creation)
		👉 Focus on how objects are created while hiding creation logic.

		Examples:
			Singleton → Ensures only one instance of a class exists.
			Factory Method → Defines an interface for creating objects, but lets subclasses decide which class to instantiate.
			Abstract Factory → Provides an interface to create families of related objects.
			Builder → Builds complex objects step by step.
			Prototype → Clones an existing object instead of creating a new one.

	2️⃣ Structural Patterns (Object composition)
		👉 Focus on how classes and objects are combined to form larger structures.

		Examples:
			Adapter → Converts one interface into another that a client expects.
			Bridge → Separates abstraction from implementation.
			Composite → Composes objects into tree structures (e.g., folder-file structure).
			Decorator → Adds responsibilities to objects dynamically without modifying their class.
			Facade → Provides a simple interface to a complex subsystem.
			Proxy → Provides a placeholder for another object to control access.
			Flyweight → Minimizes memory use by sharing objects.

	3️⃣ Behavioral Patterns (Object interaction)
		👉 Focus on how objects communicate and responsibilities are assigned.

		Examples:
			Observer → One-to-many dependency (when one object changes, dependents are notified).
			Strategy → Defines a family of algorithms and makes them interchangeable.
			Command → Encapsulates a request as an object.
			Iterator → Provides a way to access elements sequentially without exposing underlying representation.
			Template Method → Defines the skeleton of an algorithm, deferring steps to subclasses.
			Mediator → Reduces coupling by centralizing communication between objects.
			Memento → Captures an object’s state for later restoration (undo functionality).
			State → Allows an object to change its behavior when its state changes.
			Chain of Responsibility → Passes a request along a chain of handlers until one handles it.
			Interpreter → Defines a grammar and an interpreter for a language.
			Visitor → Lets you define new operations without changing the objects’ structure.

📌 Example: Singleton Pattern
	class Singleton {
	    private static Singleton instance;
	
	    private Singleton() {} // private constructor
	
	    public static Singleton getInstance() {
	        if (instance == null) {
	            instance = new Singleton();
	        }
	        return instance;
	    }
	}


	Ensures only one instance exists.
	Useful for logging, DB connections, config managers.

📌 Example: Strategy Pattern
	interface PaymentStrategy {
	    void pay(int amount);
	}
	
	class CreditCardPayment implements PaymentStrategy {
	    public void pay(int amount) {
	        System.out.println("Paid " + amount + " with Credit Card");
	    }
	}
	
	class PaypalPayment implements PaymentStrategy {
	    public void pay(int amount) {
	        System.out.println("Paid " + amount + " with PayPal");
	    }
	}

	class ShoppingCart {
	    private PaymentStrategy paymentStrategy;
	
	    public ShoppingCart(PaymentStrategy paymentStrategy) {
	        this.paymentStrategy = paymentStrategy;
	    }
	
	    public void checkout(int amount) {
	        paymentStrategy.pay(amount);
	    }
	}
	
	
	✅ Now, we can easily switch between payment methods.

Key Takeaways
	Creational → Object creation (Singleton, Factory, Builder).
	Structural → Object composition (Adapter, Decorator, Composite).
	Behavioral → Object communication (Observer, Strategy, Command).

They help you:
	Reduce code duplication.
	Achieve loose coupling.
	Increase flexibility & scalability.

👉 In short:
	Design Patterns are battle-tested solutions for common design challenges. They make software flexible, reusable, and maintainable.
