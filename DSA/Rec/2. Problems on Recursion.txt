2. Combination Sum 2
 	Approach 1: Follow simple subsequence pattern, store in Set<List<Integer>> set to avoid duplicates.
 		    But in this approach you will generate duplicates which will take an extra time.

 		    What if on the go we can decide whether this will generate duplicate or not and depending on that take it or not.
 		    Here comes the approach 2.

 	Approach 2: Everytime while going ahead check if it is equal to previous element or not. If yes skip it.
 		    Let's understand with example:

 		    Example: [1,1,1,2,2]

 		    At every moment we have two options: take it or not take it.

 		    If we took the first element currently our list holds [1],      			If we didn't took it our list is empty.
 		    now we are at the second index. Again we have two options: 				We again have two options for the first index(since we didn't took it,
 		    take it or not take it.								it is the first element). Now we have two option take it or not take it.
 													If we took it again at the first element there will be 1 and the list will be [1].

 		    Now this will generate elements like:						If we took it, the lists generated will be:
 		    [1,1,2],[1,2,2],...									[1,1,2],[1,2,2],...

 		    Hence, they both will start giving the same lists.



 		    Let's move ahead and try to understand in better way:
 		    1. Suppose we took the first element, our current list is [1].
 		       Now we reached at index 1, we can take it or not take it.
 		       If we took it our second element becomes 1.
 		       Hence, list is [1,1].

 		    2. If we decided not to take index 1 and move ahead then at index 2
 		       we decided to take index 2.
 		       Hence, our list becomes [1,1].
 		       Again the second index is 1, which is similar to case 1.
 		       Hence we won't take it


 	If you didn't get this, let's try another way:

 	Example: [1,1,1,2,2]
 	You can take any index element as your first element, right?
 	Suppose you choose 0th index as your first element then it won't make any sense to choose 1st or 2nd index as your first element becuase they are equal to the 0th index.
 
 	Now if you are choosing the 1st index as the second element, will it really make any sense to choose the 3rd index as the second element?
 	No, they both will generate the same subsequences.

 	I hope  you get the point.

3. Subset 2
 	Similar to previous problem, with a minute tweak.
 	public void f(int i, int n, int[] nums, List<Integer> list, List<List<Integer>> ans) {
 	// This will handle all the list when we take the element
        if(i == n) {
            ans.add(new ArrayList<>(list));
            return;
        }

        for(int start = i; start < n; start++) {
            if(start != i && nums[start] == nums[start - 1]) continue;

            list.add(nums[start]);
            f(start + 1, n, nums, list, ans);
            list.remove(list.size() - 1);
        }

 	// This will handle all the elements when we don't take the elements.
        ans.add(new ArrayList<>(list));
    }

    public List<List<Integer>> subsetsWithDup(int[] nums) {
        int n = nums.length;
        Arrays.sort(nums);

        List<List<Integer>> ans = new ArrayList<>();
        f(0, n, nums, new ArrayList<>(), ans);

        return ans;
    }

5. Permutation Sequence
	Hard
	You need to think, how many you can skip to jump to your answer.
	
	Example: [1,2,3,4] and k = 17
	If we consider 0 based indexing, we need to find k = 16 permutation.
	
	If we try placing 1 at 0th index, number of permutation = 6
	2 at 0th index, number of permutations = 6
	Similarly for 3 and 4.

	For 16: 6 + 6 + (3rd one will contain the desired answer)
	If we divide k by 6((n - 1)!) = 16/6 = 2, it means you need to take 2nd index in your answer.
	And k will reduce to k = k % 6((n - 1)!) i.e. k = 16 % 6 = 4.
	And we will remove 2nd index.

	Now our array will become: [1,2,4] and k = 4.
	Again, we can try placing any of the three numbers at 0th index. Number of permutation generated in each case will be 2 which is (n - 1)! = (3 - 1)! = 2! = 2.
	Again we will take k / (n - 1)! index i.e. 4 / 2 = 2nd index. 
	And k will reduce to k = k % 2((n - 1)!).

	We will continue for n times which is 4 times because in 4 times we will be taking all the 4 elements in correct order.
