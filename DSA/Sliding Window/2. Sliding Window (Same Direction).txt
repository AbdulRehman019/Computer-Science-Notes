Sliding Window (Same Direction)
	This pattern is a game-changer when it clicks — so let’s master it.

	🔍 Sliding Window: Core Idea
		You maintain a window (usually a subarray or substring), using two pointers:
			right pointer: expands the window to include more elements
			left pointer: shrinks the window when a constraint is violated

		This pattern shines when the problem says:
			Type1: “Find the longest/shortest subarray/subsequence that satisfies a condition” --> Use Sliding window
			Type2: “Count subarrays with something…” Or "No. of subarrays with some conditions" --> Difficult one but solved using the given template only.
			Type3: “Minimize/maximize something in a window” Or "Shortest/Minimum window with some conditions"

		*** Important *** right - left + 1 gives you size and number of subarrays including right. 
 		count++ will give you that valid subarray. 

	🧠 Template
		int left = 0;
		for (int right = 0; right < n; right++) {
		    // Expand the window by including nums[right]
		
		    while (window violates condition) {
		        // Shrink the window from the left
		        left++;
		    }
		
		    // Update result based on current window size or contents
		}

	Logic: 
		Usually in these type of problem we will have three things common: left = 0, right = 0. maxLen = 0. 
		Fourth variable will vary: sum, count.
		We will go: 
			while(right < n), 
			perform some operation(Expand no matter what), 
			check whether we are violating the condition or not,
			if yes, we will shrink and move back to right condition and update our answer
			if no, we will go ahead and update our answer 
			Like in above template

	Notes:
		1. Instead of jumping left to a index, try to do left++, you will avoid mistakes.
		2. Problems including maximum/minimum number we play on whaterver maximum or minimum we need to find. 
		   Like in Maximum consecutive ones, we play on count of flipped zeroes
		   And in Fruit into Baskets, we played on number of type of fruits in the window.

*************************************************** Fruit into Baskets *********************************************************
First i thought of the approach in which i will track two types of fruits with their last appeared index.
And when third type comes, i will remove the first type index, make second as first and third as second.
But this approach fails when the input is scattered like: 1, 2, 1, 3, 1, 2

Hence, i take into account the frequency and remove a element only when frequency of that element is 0 in that window.
Hence, i take into account
We track the number of elements in a window.
When the first type came i inserted it in map with its frequency 1.
When the second type came i inserted it in map with its frequency 1.
If any of the type comes again i increased the frequency.
Since, number of elements in map exceeds two, i removed elements from left and start decreasing the frequency of removed type. 
If that type becomes 0, i will remove that type and the number of elements in map will again become two(Again in correct window).

******************************************************* Longest Repeating Character Replacement *******************************************************
Instead of map, i used int[] freq = new int[26]. We can go with map too.

First i expanded, did right++, increased freq[char] and updated maxFreq.

Second i checked (r - l + 1) - maxFreq > k, it will give the number of characters changed, if it is greater than k, it means the number of characters changed 
are greater than allowed. This means window is violated we will shrink the window and bring it back in valid range.

We will update the maxLen.

Why we didn't updated maxFreq while removing characters from left?
	If suppose, k = 1 and we reached somewhere this condition: r - l + 1 = 5 and maxFreq = 3 then (r - l + 1) - maxFreq > k(1).
	We have 5 - 3 > 1. 
	Now, we will want two things either to increase the length (r - l + 1) because we want the maxLen. Or Increase the maxFreq so that window can be in correct range.
	If we don't decrease the maxFreq, then also all the length greater than current one(5) like 6, 7, 8, 9... will be invalid for maxFreq 3.
	6 - 3 > 1 or 7 - 3 > 1 and by decreasing the maxFreq we will increase the number of change characters.
	6 - 2 > 1.
	Hence the decreased maxFreq can never give the answer. 
	Difficult to think first time. 
	But if we decrease the maxFreq, by checking everytime the complexity won't increase much. And that is thinkable. 

	If 5 - 3 > 1 is invalid then 5 - 2 > 1 is definitely invalid. 
	But if 4 - 3 <= 1 is valid then maybe 4 - 2 <= 1(It is possible, it is valid or not). 
	But kuch bhi ho jo invalid window hogi wo isse pehle maxLen me aa chuki hogi. 
	It will never happen that you calculate wrong maxLen.
