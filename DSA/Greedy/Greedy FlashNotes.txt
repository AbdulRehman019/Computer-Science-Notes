1. When to sort by start vs end time
	Think: “What am I trying to optimize?”
	Sort by end time when you want to maximize the number of non-overlapping intervals (e.g., Activity Selection, #452).
	Sort by start time when you need to track overlaps or merge intervals (e.g., Meeting Rooms, Merge Intervals).

	📌 End time sorting = I want to "finish early" so I can do more.

2. Greedy with validation rollback
	You already mentioned this, now reword slightly for clarity:
	"Sometimes greedy choice may not be optimal long-term. Use max-heap to remove 'worst' past choice when needed — (e.g., #630 Course Schedule III)."

3. Preprocessing: Merging intervals before applying greedy
	Some problems need you to merge overlapping intervals before applying greedy logic.

	Example:
		Merge overlapping intervals (e.g., [1,3], [2,6]) → [1,6]
		Then apply logic (e.g., for placing points, cameras, etc.)

4. Job sequencing nuance
	Job Sequencing (with deadline) is a special greedy type:
		Sort by profit or value (not time)
		Then try to place job in the latest available time slot before deadline
		This is not purely interval, but still greedy. Add this distinction:
			"Not all greedy problems are sorted by time — Job Sequencing sorts by profit and works backward in time."

5. Overlapping count technique (sweep line)
	For problems like:
		Minimum meeting rooms
		Maximum people in room at once

	You can use two arrays (start and end), sort both, and simulate a sweep line.
		“When you care about how many overlaps at a moment → consider sweep line using two sorted arrays.”
