 		  No chance ahead children will accept that cookie, because their desire will be bigger. Hence, move the index j.
 		  If the cookie is bigger than the desire of children, child will accept it. Hence, move i and increase the count.

2. Gas Station(#134)	--> Prefix sum with greedy
 	Difficulty: Medium
 
 	Brute Force: We will start from every index and check if it is possible or not.

 	Better: If gas[i] < cost[i], we can skip that.
 		Suppose we start from 1st index and couldn't reach 4th index.
 		Then, it is confirm that if we start from 2nd index, its not possible to reach 4th index.
 		Because 1st index might have brought some extra power and if it was not possible for that then it won't be possible for any index between 1 and 4.
 		Hence, we can directly start from 4th index, that is it possible from 4th index or not.

 	Optimal:
 		class Solution {
 		    public int canCompleteCircuit(int[] gas, int[] cost) {
 		        int total = 0, tank = 0, start = 0;
 		        for(int i = 0; i < gas.length; i++) {
 		            int gain = gas[i] - cost[i];
 		            total += gain;
 		            tank += gain;
 		            if(tank < 0) {
 		                start = i + 1;
 		                tank = 0;
 		            }
 		        }
 		        return total < 0 ? -1 : start;
 		    }
 		}

 		It is only possible to make a round trip, if summation of difference of gas[i] - cost[i] >= 0.
 		Hence, if total >= 0, we return start otherwise -1.

8. Valid Parenthesis String(#678)
 	Brute: Recursion + Stack
 	       You can use Backtracking and store the characters in stack.
 	       Problem with this approach is no way you can memoize it. So better not use it.

 	Better: Recursion + Count
 		You can use count to maintain the characters.
 		If ch == '(' then count + 1
 		If ch == ')' then count - 1;
 		If ch == '*', try all three count - 1, count + 0, count + 1

 		If at any point count < 0 return false
Better: Memoize + Tabulation + Space Optimize:




 	Optimal: Basic appraoch of using count. But if we get '*' then we have three posibility: count - 1, count + 0, count + 1
 		 But we cannot maintain it using single count variable.
 		 We introduced third vaiable to store the range of possible answers, mini and maxi.
 		 If ch == '(', then mini++ and maxi++.
 		 If ch == ')', then mini-- and maxi--. If mini < 0, then mini = 0.
 		 If ch == '*', then mini can go to mini - 1 or mini + 0 or mini + 1.
 		 And maxi will go maxi - 1 or maxi + 0 or maxi + 1.

10. Queue Reconstruction by Height(#406)
 	I sorted according to their height in descending order and if people[i][1] =  4, i placed it at 4th index.
 	It means 4 people bigger than him will come before him and he can be anywhere after this index.
 	Why sorted in descending order?
 		Consider this example: [7,0], [5,0]

 	If i placed [5,0] before and then i know none of the people taller than him are before.
 	I will move to [7,0] and place him at 0th index but this will make one person taller than [5,0] before him.

 	Shorter people don't disturb taller people.
 	Hence, place taller people first, hence sort in decreasing order.

11. Course Schedule III(#630)
 	In this problem, you might think of two things.
 	First, to choose the courses with earlier deadlines to finish first.
 	Or you might think to choose those courses which are taking less time to finish.

 	Here, you need to use combo of both.
 	First sort it according to deadlines i.e. according to 1st index.
 	Secondly, use priority queue to maintain the courses which are taking more time.

 	Start iterating over courses, add them in prirority queue and if at any moment the days crosses the current deadline remove the day which is taking more.
 	If at any moment the days crosses the current deadline, you have two options:
 	Either remove the current one, don't take it or remove the one which is taking more day.
 	If we remove the one taking more day we will spend less number of days and we will be having more days for future courses.
