What is a memory leak in Java? Can you give an example of a situation where this might occur?
	A memory leak in Java refers to a situation where memory that is no longer needed is not released by the garbage collector, leading to excessive memory usage. Over time, this can 	cause the application to consume more memory than necessary, which might result in OutOfMemoryError or poor application performance due to the system running out of memory.

	In Java, memory leaks typically occur when objects are no longer required but still remain in memory because there are still references to them, preventing the garbage collector 	from freeing up the space. This leads to memory being "leaked" as the garbage collector can't reclaim it.

Causes of Memory Leaks in Java
	Unintentional Object Retention:
	Keeping references to objects that are no longer in use (e.g., static fields, collections, etc.) can prevent the garbage collector from reclaiming the memory.

	Event Listeners and Callbacks:
	If event listeners or callbacks are not properly removed after use, they can hold references to objects, preventing them from being garbage collected.

	Thread Local Variables:
	If thread-local variables are not cleared, the objects stored in them may not be garbage collected.

	Improper Use of Caching:
	Storing objects in caches without any eviction mechanism or clearing strategy can lead to memory leaks.

Example of a Memory Leak in Java
	Here’s an example of how a memory leak can occur due to keeping unnecessary references to objects in a collection:
		import java.util.ArrayList;
		import java.util.List;
		public class MemoryLeakExample {
			private static List<Object> memoryLeakList = new ArrayList<>();
				public static void main(String[] args) {
				    // Simulating a memory leak situation
				    for (int i = 0; i &lt; 1000; i++) {
				        Object obj = new Object();
				        memoryLeakList.add(obj); // Adding objects to a static list
				    }

				    // The objects in memoryLeakList are never removed, causing a memory leak
				    // As memoryLeakList is static, it will hold all these references even when not needed
				    System.out.println(&quot;Objects are added to the list, but never removed!&quot;);
				}
		}

Explanation:
	The static list memoryLeakList keeps adding Object instances in each iteration of the loop.
	However, these objects are never removed from the list.
	Because the list is static, the reference to each object is maintained for the entire lifetime of the program.
	Over time, this can lead to memory consumption growing unnecessarily, especially if many such objects are added in a long-running application.

	Even though the objects are no longer needed after some point, they remain in memory because the static list still holds references to them, preventing the garbage collector from 	reclaiming that memory.

❓ How to Avoid Memory Leaks in Java
	Remove Unnecessary References:
	Ensure that objects are dereferenced when they are no longer needed. For example, remove items from collections or set objects to null when they are no longer in use.

	Weak References:
	If you need to cache objects but don't want them to prevent garbage collection, consider using WeakReference or SoftReference to allow the garbage collector to reclaim memory when 	needed.

	Event Listener Cleanup:
	Always unregister event listeners or callbacks after they are no longer needed to avoid holding onto objects unnecessarily.

	Avoid Static References:
	Avoid using static fields to store references to objects unless absolutely necessary, especially in long-running applications.

	Use Profiling Tools:
	Use tools like VisualVM, Eclipse MAT (Memory Analyzer Tool), or JProfiler to detect and analyze memory leaks in your Java applications.

Example of Fixing the Memory Leak
	In the previous example, a simple fix would be to clear the list when it is no longer needed:
		public class MemoryLeakFixExample {
		    private static List<Object> memoryLeakList = new ArrayList<>();
			public static void main(String[] args) {
		    		for (int i = 0; i &lt; 1000; i++) {
        				Object obj = new Object();
        				memoryLeakList.add(obj); // Adding objects to a list
    				}

    				// Properly removing objects when no longer needed
    				memoryLeakList.clear();  // This allows the garbage collector to reclaim memory

    				System.out.println(&quot;Objects are cleared, memory leak avoided!&quot;);
			}
	}

	By calling memoryLeakList.clear(), we remove all references from the list, allowing the garbage collector to reclaim the memory used by those objects.

Conclusion
	A memory leak in Java occurs when objects are not properly dereferenced, and thus the garbage collector cannot reclaim the memory.
	Memory leaks can occur due to unintentional retention of objects in collections, event listeners, static variables, etc.
	It's crucial to identify and resolve memory leaks, especially in long-running applications, to avoid performance degradation or crashes due to excessive memory usage. 
	Tools like memory profilers can be helpful in detecting and addressing such issues.
