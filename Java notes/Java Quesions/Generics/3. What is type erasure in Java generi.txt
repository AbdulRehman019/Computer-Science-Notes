What is type erasure in Java generics, and how does it affect the way generics are used?
Type erasure is a process in Java where the generic type information is removed (erased) during compilation. This means that the generic types you specify in your code are only available at compile-time and are replaced with their raw types or bounds during runtime.



Why Type Erasure Exists


Backward Compatibility:
Generics were introduced in Java 5, and type erasure ensures that code written with generics can run on older versions of the JVM that do not support them.


Unified Bytecode:
Since the Java Virtual Machine (JVM) does not support generics natively, type erasure ensures a unified bytecode structure by removing generic type information.


❓ How Type Erasure Works


Replacing Type Parameters:
Unbounded type parameters (<T>) are replaced with Object.
Bounded type parameters (<T extends Number>) are replaced with their upper bound (e.g., Number).


Inserting Casts:
Casts are added automatically to ensure type safety where generic types are used.


Removing Generic Information:
Generic type information is stripped from methods and classes, and raw types are used instead.


Example of Type Erasure


// Generic Method
public class Example<T> {
    public void print(T item) {
        System.out.println(item);
    }
}
// After Type Erasure
public class Example {
public void print(Object item) {
System.out.println(item);
}
}


Implications of Type Erasure


No Runtime Type Information:
Generic type information is not available at runtime due to type erasure.
java List<String> stringList = new ArrayList<>(); List<Integer> intList = new ArrayList<>(); System.out.println(stringList.getClass() == intList.getClass()); // true


Limitations in Generics:
No Instance Creation with Generic Types:
You cannot create instances of a generic type.
java public class Example<T> { // Compilation error T item = new T(); }

No Primitive Generics:
Generics work only with reference types, not primitives. Use wrappers like Integer for int.

No Generic Arrays:
Arrays cannot be created with generic types due to runtime type information being unavailable.
java List<String>[] array = new ArrayList<String>[10]; // Compilation error



Type Casting at Runtime:
Casts are added automatically to ensure type safety, but improper use of generics can still lead to ClassCastException.
java List rawList = new ArrayList<>(); rawList.add(10); // Adding Integer String value = (String) rawList.get(0); // Runtime ClassCastException


Best Practices to Avoid Issues with Type Erasure


Use Proper Bounds:
Specify bounds to restrict type parameters and provide type safety.
java public <T extends Number> void print(T number) { System.out.println(number.doubleValue()); }


Avoid Mixing Raw and Parameterized Types:
Do not mix raw types (e.g., List) and parameterized types (e.g., List<String>).


Use @SuppressWarnings Cautiously:
When suppressing warnings related to generics, ensure type safety manually.


Understand Limitations:
Be aware of generic constraints, such as the inability to create generic arrays or work with primitives.


Conclusion


Type erasure is a fundamental concept of Java generics that ensures backward compatibility by removing generic type information at runtime. While it enables powerful compile-time type safety, it also imposes certain limitations, such as the lack of runtime type information and restrictions on usage with primitives and arrays. Understanding type erasure helps developers use generics effectively while avoiding potential pitfalls.
